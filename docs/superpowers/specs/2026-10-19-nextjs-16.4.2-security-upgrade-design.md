# Next.js 16.4.2 Security Upgrade & Hardening Specification

- **Date:** 2026-10-19
- **Target:** `frontend/` Next.js App Router
- **Status:** Approved for Implementation Planning

---

## 1. Background & Problem Statement

Pemindaian port 443/tcp mendeteksi 5 kerentanan keamanan berisiko tinggi (High Severity) pada Next.js versi `16.2.2`:

| CVE | CVSS | Versi Terdampak | Perbaikan di | Ringkasan Kerentanan |
|---|---|---|---|---|
| **CVE-2026-44578** | 8.6 | 13.4.13 s.d. <15.5.16 & 16.2.5 | 15.5.16, **16.2.5** | SSRF melalui crafted WebSocket upgrade request pada server mandiri (Node.js built-in server pada `output: 'standalone'`). |
| **CVE-2026-94483** | 8.3 | 16.0.0 s.d. 16.3.8 | **16.3.8** | SSRF via DNS rebinding pada Image Optimization ketika mencocokkan URL remote di `images.remotePatterns`. |
| **CVE-2026-64649** | 8.3 | 14.1.1 s.d. 15.5.20 & 16.0.0 s.d. 16.2.10 | 15.5.21, **16.2.11** | SSRF saat Server Action forward/redirect request akibat Host header manipulasi pada custom server unpinned. |
| **CVE-2026-64645** | 8.3 | 12.0.0 s.d. 15.5.20 & 16.0.0 s.d. 16.2.10 | 15.5.21, **16.2.11** | SSRF / Open Redirect pada aturan `rewrites()` atau `redirects()` yang menggunakan input request kontrol hostname eksternal. |
| **CVE-2026-64642** | 8.3 | 16.0.0 s.d. 16.2.10 | **16.2.11** | Bypass autentikasi middleware/proxy pada Next.js App Router dengan Turbopack dan entri tunggal di `config.i18n.locales`. |

Aplikasi saat ini menggunakan `next@16.2.2`, `output: 'standalone'`, berjalan di Node.js container (`Dockerfile`). Karena `16.2.2` berada di bawah `16.3.8`, aplikasi terdampak oleh kelima kerentanan di atas.

---

## 2. Proposed Architecture & Remediation Strategy

### 2.1 Dependensi Target
Upgrade paket Next.js dan ESLint config ke versi rilis stabil terbaru:
- `next`: `16.2.2` $\to$ `16.4.2`
- `eslint-config-next`: `16.2.2` $\to$ `16.4.2`

Versi `16.4.2` $\ge$ `16.3.8`, sehingga seluruh 5 CVE tertambal tanpa berpindah major framework version (tetap di seri 16.x).

### 2.2 Kompatibilitas Framework & Runtime
- **React**: Tetap pada `19.2.4` (didukung penuh oleh Next.js 16.4.2).
- **Node.js**: Minimum Node 20 LTS (sesuai `Dockerfile` `FROM node:20-alpine`).
- **Bundler / Tooling**: Kompatibel dengan Turbopack dan webpack build.

### 2.3 Hardening Konfigurasi (`next.config.mjs` & Deploy)
1. **Image Optimization**:
   - `images.unoptimized: true` tetap dipertahankan.
   - Entri `images.remotePatterns` diaudit agar hanya merujuk ke endpoint backend terpercaya dan Unsplash.
2. **Reverse Proxy & Host Headers (Defense-in-depth)**:
   - Pastikan reverse proxy di depan port standalone `3002` selalu menyuplai `Host` header yang valid dari domain publik resmi, mencegah header spoofing untuk Server Actions.
3. **Standalone Output**:
   - `output: 'standalone'` tetap dipertahankan untuk container Docker minimalis. Server binary yang dihasilkan pada `16.4.2` sudah membawa patch WebSocket SSRF handler.

---

## 3. Verification & Acceptance Criteria

1. **Dependency Integrity**:
   - `package.json` dan `package-lock.json` mengarah ke Next.js `16.4.2`.
   - `npm ls next` mengonfirmasi resolusi versi `16.4.2`.
2. **Linting Check**:
   - `npm run lint` selesai tanpa error kompatibilitas ESLint.
3. **Build Check**:
   - `npm run build` sukses mengompilasi rute App Router dan menghasilkan artefak `.next/standalone`.
4. **Unit Test Pass**:
   - `npm test -- --run` (vitest unit test suites) lulus 100%.

---

## 4. Rollback Plan

Jika ditemukan incompatibilitas runtime tak terduga:
1. Revert perubahan di `frontend/package.json` dan `frontend/package-lock.json` via `git checkout package.json package-lock.json`.
2. Jalankan `npm install` untuk mengembalikan ke `16.2.2`.
3. Terapkan alternatif mitigasi per-CVE (misal upgrade minimum ke `16.3.8` atau proteksi Nginx filter).
